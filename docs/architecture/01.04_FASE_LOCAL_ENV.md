## MÓDULO I — Análisis: LocalStack Community vs Pro

### Clasificación de servicios de Metri Engine por disponibilidad

| Servicio AWS    | Equivale a                   | LocalStack                  | Alternativa 100% Free                 | Compatibilidad SDK   |
| :-------------- | :--------------------------- | :-------------------------- | :------------------------------------ | :------------------- |
| **DynamoDB**    | Datahike, Schemas, Quota     | ⚠️ Requiere token/cuenta    | `amazon/dynamodb-local` (oficial AWS) | ✅ Idéntica          |
| **S3**          | Data Lake, resultados Athena | ⚠️ Requiere token/cuenta    | `minio/minio`                         | ✅ API S3 compatible |
| **SQS FIFO**    | Outbox + DLQ                 | ⚠️ Requiere token/cuenta    | `softwaremill/elasticmq-native`       | ✅ 100% compatible   |
| **Athena**      | Motor OLAP Aegis             | ❌ Solo Pro / bigdata image | `InMemoryQueryEngine` (stub Clojure)  | N/A — stub en tests  |
| **Kinesis**     | BulkIngest OLAP              | ❌ Solo Pro                 | `InMemoryStreamWriter` (stub Clojure) | N/A — stub en tests  |
| **EventBridge** | Fault Bus Sherlog            | ❌ Solo Pro                 | `InMemoryEventBus` (stub Clojure)     | N/A — stub en tests  |

## MÓDULO III — `docker-compose.yml` Completo

```yaml
version: "3.8"

services:

  # ── DynamoDB Local (Oficial AWS) — OLTP Datahike + Schemas + Quota ───────
  dynamodb-local:
    image: amazon/dynamodb-local:latest
    container_name: metri-dynamodb-local
    ports:
      - "8000:8000"
    command: "-jar DynamoDBLocal.jar -sharedDb -dbPath /data"
    volumes:
      - dynamodb-data:/data
    healthcheck:
      test: ["CMD-SHELL", "curl -sf http://localhost:8000/shell/ || exit 1"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 5s

  # ── MinIO — S3 Compatible (Data Lake local) ───────────────────────────────
  minio:
    image: minio/minio:latest
    container_name: metri-minio
    ports:
      - "9000:9000"
      - "9001:9001"
    environment:
      MINIO_ROOT_USER: minioadmin
      MINIO_ROOT_PASSWORD: minioadmin
    command: server /data --console-address ":9001"
    volumes:
      - minio-data:/data
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9000/minio/health/live"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 5s

  # Crea los buckets necesarios la primera vez
  minio-init:
    image: minio/mc:latest
    depends_on:
      minio:
        condition: service_healthy
    entrypoint: >
      /bin/sh -c "
        mc alias set local http://minio:9000 minioadmin minioadmin;
        mc mb --ignore-existing local/metri-lake-local;
        mc mb --ignore-existing local/metri-athena-results-local;
        echo 'MinIO buckets OK';
      "

  # ── ElasticMQ — SQS FIFO Compatible (Outbox EDA) ─────────────────────────
  elasticmq:
    image: softwaremill/elasticmq-native:latest
    container_name: metri-elasticmq
    ports:
      - "9324:9324"
      - "9325:9325"
    volumes:
      - "./infra/elasticmq/custom.conf:/opt/elasticmq.conf"

  # ── Valkey 7.2 — Session Store ────────────────────────────────────────────
  valkey:
    image: valkey/valkey:7.2-alpine
    container_name: metri-valkey-local
    ports:
      - "6379:6379"
    command: >
      valkey-server --save "" --appendonly no --loglevel warning
    healthcheck:
      test: ["CMD", "valkey-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 5
      start_period: 3s

  # ── DynamoDB Init — Crea las tablas en DynamoDB Local ────────────────────
  dynamodb-init:
    image: amazon/aws-cli:latest
    depends_on:
      dynamodb-local:
        condition: service_healthy
    environment:
      AWS_ACCESS_KEY_ID: test
      AWS_SECRET_ACCESS_KEY: test
      AWS_DEFAULT_REGION: us-east-1
    entrypoint: /bin/sh -c "
      aws dynamodb create-table --endpoint-url http://dynamodb-local:8000
        --table-name metri-datahike-local
        --attribute-definitions AttributeName=Id,AttributeType=S
        --key-schema AttributeName=Id,KeyType=HASH
        --billing-mode PAY_PER_REQUEST 2>/dev/null || true;
      aws dynamodb create-table --endpoint-url http://dynamodb-local:8000
        --table-name metri-schemas-local
        --attribute-definitions AttributeName=PK,AttributeType=S
        --key-schema AttributeName=PK,KeyType=HASH
        --billing-mode PAY_PER_REQUEST 2>/dev/null || true;
      aws dynamodb create-table --endpoint-url http://dynamodb-local:8000
        --table-name metri-quota-local
        --attribute-definitions AttributeName=PK,AttributeType=S AttributeName=SK,AttributeType=S
        --key-schema AttributeName=PK,KeyType=HASH AttributeName=SK,KeyType=RANGE
        --billing-mode PAY_PER_REQUEST 2>/dev/null || true;
      echo 'DynamoDB tables OK';
    "

volumes:
  dynamodb-data:
    driver: local
  minio-data:
    driver: local
```

## MÓDULO IV — Configuración ElasticMQ

Archivo: `infra/elasticmq/custom.conf`

Las colas FIFO se pre-configuran **declarativamente** en el archivo de configuración de ElasticMQ, sin scripts de init externos:

```hocon
include classpath("application.conf")

node-address { protocol = http; host = "*"; port = 9324 }
rest-sqs     { enabled = true;  bind-port = 9324; sqs-limits = strict }
rest-stats   { enabled = true;  bind-port = 9325 }

queues {
  "metri-outbox-dlq.fifo" {
    fifo = true
    contentBasedDeduplication = true
    defaultVisibilityTimeout = 10 seconds
  }
  "metri-outbox.fifo" {
    fifo = true
    contentBasedDeduplication = true
    defaultVisibilityTimeout = 30 seconds
    deadLettersQueue {
      name            = "metri-outbox-dlq.fifo"
      maxReceiveCount = 3
    }
  }
}
```

> [!TIP]
> ElasticMQ acepta el mismo protocolo SQS que AWS SDK v2. El URL del endpoint es
> `http://localhost:9324` y el Account ID ficticio es `000000000000`.

## MÓDULO VI — Stubs para Athena / Kinesis / EventBridge

Los tres servicios Pro de LocalStack se sustituyen con stubs in-memory de Clojure
definidos en `01.02_FASE_CLIENTES_INFRAESTRUCTURA.md`. Se inyectan en `system.dev.edn`:

```clojure
;; resources/system.dev.edn — Overrides para entorno local
;; Sustituye clientes AWS Pro por stubs in-memory

:infra/athena
  #ig/ref :infra/stubs/athena   ;; InMemoryQueryEngine

:infra/kinesis
  #ig/ref :infra/stubs/kinesis  ;; InMemoryStreamWriter

:infra/eventbridge
  #ig/ref :infra/stubs/eventbridge ;; InMemoryEventBus
```

```clojure
;; resources/system.dev.edn — stubs declarados
:infra/stubs/athena     {}
:infra/stubs/kinesis    {}
:infra/stubs/eventbridge {}
```

```clojure
;; ns: metri.infrastructure.stubs.athena
(defrecord InMemoryQueryEngine [queries-atom]
  proto/IQueryEngine
  (start-query! [_ sql _db]
    (let [id (str "stub-qid-" (count @queries-atom))]
      (swap! queries-atom conj {:sql sql :id id})
      [:ok {:execution-id id}]))
  (get-query-results [_ execution-id]
    [:ok {:execution-id execution-id :columns [] :rows []}]))

(defmethod ig/init-key :infra/stubs/athena [_ _]
  (println "    -> Athena STUB: InMemoryQueryEngine (sin AWS)")
  (->InMemoryQueryEngine (atom [])))
```

## MÓDULO VIII — Flujo de PoC: Servidor gRPC Local

### 8.1 — Modo A: Servidor gRPC Netty (recomendado)

Este es el modo para pruebas reales contra el endpoint gRPC:

```bash
# Un solo comando — compila + levanta infra + arranca el servidor gRPC
./scripts/local/start-grpc.sh

# El script hace:
#  1. docker compose up -d  (DynamoDB Local, MinIO, ElasticMQ, Valkey)
#  2. clj -T:build uber     (compila target/metri-engine.jar)
#  3. java -jar ...         (arranca Netty en localhost:9090)
```

Cuando el servidor esté listo verás:

```
✓ Metri Engine READY — gRPC listening on port 9090
```

#### Verificar el servidor con grpcurl

```bash
# Instalar grpcurl (si no está)
brew install grpcurl

# Health check — confirma que el servidor está SERVING
grpcurl -plaintext localhost:9090 grpc.health.v1.Health/Check
# Respuesta: { "status": "SERVING" }

# Listar todos los servicios registrados
grpcurl -plaintext localhost:9090 list
# Respuesta: metre.MetriService, grpc.health.v1.Health

# Describir el contrato completo de MetriService
grpcurl -plaintext localhost:9090 describe metre.MetriService

# Describir un mensaje específico
grpcurl -plaintext localhost:9090 describe metre.TransactionRequest
```

#### Invocar RPCs con grpcurl

```bash
# rpc Transact — crear una entidad
grpcurl -plaintext \
  -H 'authorization: Bearer test-token-local-01' \
  -d '{
    "entity_type": "user",
    "action": "CREATE",
    "payload": {"name": "Ana García", "email": "ana@demo.com"}
  }' \
  localhost:9090 metre.MetriService/Transact

# rpc Discovery — explorar schemas del Códice
grpcurl -plaintext \
  -H 'authorization: Bearer test-token-local-01' \
  -d '{"entity_type": "user"}' \
  localhost:9090 metre.MetriService/Discovery

# rpc Explore — listar entity types disponibles
grpcurl -plaintext \
  -H 'authorization: Bearer test-token-local-01' \
  -d '{}' \
  localhost:9090 metre.MetriService/Explore
```

> [!TIP]
> `GRPC_REFLECTION_ENABLED=true` (activado en el script) permite que `grpcurl`
> descubra el schema del servicio sin necesitar el `.proto` localmente.
> En producción esta flag es `false`.

### 8.2 — Modo B: sam local invoke (Lambda individual)

Para probar el handler Lambda de forma aislada (NO gRPC, responde en HTTP):

```bash
# Solo levantar infraestructura (sin servidor gRPC)
docker compose up -d

# Compilar y construir
clj -T:build uber && sam build

# Invocar una vez con evento JSON
sam local invoke MetriEngineFunction \
  --event events/poc_request.json \
  --env-vars env.json

# Servidor HTTP continuo en localhost:3001
sam local start-lambda --env-vars env.json

# En otra terminal — invocar via AWS CLI
aws lambda invoke \
  --function-name MetriEngineFunction \
  --endpoint-url http://localhost:3001 \
  --payload file://events/poc_request.json \
  --cli-binary-format raw-in-base64-out \
  /tmp/response.json && cat /tmp/response.json
```

> [!NOTE]
> El Modo B responde en `localhost:3001` con HTTP/1.1 JSON — **no es gRPC**.
> Sirve para validar el handler Lambda de forma aislada antes del despliegue.
> Para pruebas de integración reales usar el **Modo A** (`localhost:9090`).
