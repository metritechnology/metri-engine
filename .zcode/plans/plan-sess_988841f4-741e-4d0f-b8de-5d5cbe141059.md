# Plan: SOLID + DRY en `src/eav/writer/transact.rs`

## Diagnóstico

1. **DRY**: `transact_inner` (líneas 209–577) y `transact_bulk_deferred` (582–813) duplican ~200 líneas casi verbatim (guards, delta, retracts, enriquecimiento, entity_type, outbox, FTS, registro tx). Además, el loop de proyecciones (405–461) re-duplica validación de atributos + assert + enrich + entity_type.
2. **SRP**: `transact_inner` hace 7 trabajos: validación de registry, planificación de datoms, política de outbox, despacho FTS, ejecución transaccional, invalidación de cache y auditoría.
3. **DRY (constantes)**: los attr_ids de sistema 0–4 y sus nombres son literales inline en `enricher.rs:35-118` Y en `get_active_attributes` (`transact.rs:1017-1026`).
4. **SRP (helpers ajenos)**: `datom_value_to_json`/`datom_map_to_json`/`compute_transact_delta` viven en transact.rs pero los consumen 4 módulos externos (`janus_router/saga.rs:224`, `infrastructure/domain_event_bus.rs:121`, `infrastructure/materialization/gateway.rs:38`, `janus_router/tests/saga_tests.rs:351`).
5. **Testabilidad**: toda la lógica pura está incrustada en métodos async con I/O — los 9 tests del writer son `#[ignore]` de integración contra DynamoDB Local. Cero cobertura unitaria del camino de escritura.

Idioma del repo a seguir: plan-as-data puro (`chunker.rs`, `QueryExecutionPlan`) y el seam de trait inyectado (`constraints::ConstraintPlanner` + contexto de referencias + `plan_all`). Docs de módulo en español explicando el porqué.

## Arquitectura objetivo

```
src/eav/writer/
├── transact.rs        EavWriter: SOLO orquestación I/O (~250 líneas)
├── system_attrs.rs    NUEVO — fuente única de attr_ids/nombres de sistema
├── datom_plan.rs      NUEVO — planificador puro de datoms (payload y entidades)
├── outbox.rs          NUEVO — generación de fila outbox + helpers JSON/delta
├── fts_dispatch.rs    NUEVO — política de despacho FTS (spawn tras commit)
├── cache_policy.rs    NUEVO — invalidación EAV_CACHE/AEVT (inmediata vs diferida)
├── enricher.rs        usa system_attrs (sin literales)
├── constraints/       intacto (ya es el ejemplo del patrón)
└── tests/writer_tests.rs  intactos + nuevos tests unitarios puros
```

**transact.rs queda como orquestador**: valida registry → genera ids → lee atributos activos (I/O, se queda aquí) → `datom_plan::plan_*` (puro) → `outbox::generate` → proyecciones vía el mismo `plan_entity_datoms` → dedup → `build_write_items` → tx_registry → constraints → guard de límite → commit → `cache_policy::invalidate` → `fts_dispatch::await_all`. Un solo `transact_inner` con:

```rust
struct TxOptions<'a> {
    projections: Vec<SagaProjection>,
    actor: Option<&'a str>,
    forced_tx: Option<u64>,   // seam de prueba actual
    cache: CachePolicy,       // Immediate | Deferred
}
```

`transact`, `transact_with_projections`, `transact_with_tx` y `transact_bulk_deferred` se vuelven wrappers finos — la bulk de ~230 líneas pasa a ~6. **API pública intacta**: firmas de `EavWriter::new/with_planners/transact*/reader/quota_ledger/client/table` no cambian; los 4 consumidores externos de los helpers JSON se actualizan al nuevo path.

## Fases (cada una compila y deja tests en verde)

**Fase 0 — Línea base.** `cargo test` (unit), `cargo clippy --all-targets`; levantar DynamoDB Local (`make infra`) y correr los tests del writer (`cargo test --lib eav::writer:: -- --ignored`) para confirmar que los 9 pasan ANTES de tocar nada.

**Fase 1 — `system_attrs.rs`.** Constantes `ULID=0, TYPE=1, TENANT=2, CREATED_AT=3, UPDATED_AT=4` + nombres + `fn name_of(attr_id) -> Option<&'static str>`. Adoptar en `enricher.rs` (elimina 10 literales) y en `get_active_attributes` (elimina el match hardcodeado). Cambio de renombre puro, cero comportamiento.

**Fase 2 — `outbox.rs`.** Mover `maybe_generate_outbox` (no usa `self`) como fn libre `generate_outbox_datoms(...)`; mover `datom_value_to_json`, `datom_map_to_json`, `compute_transact_delta`; actualizar los 4 call sites externos. Tests unitarios nuevos: outbox para create/update/delete, `disable_eda`, `outbox_event` no anida outbox, payload aplanado con `id`.

**Fase 3 — `datom_plan.rs`.** Extraer el núcleo puro:
- `plan_payload_datoms(payload, entity_id, tx_id, active_attrs) -> Result<DatomPlan>` — guard de no-upsert, retracts de DELETE, retract+assert de UPDATE, enrich, entity_type legacy, delta, deleted_attrs, requests FTS.
- `plan_entity_datoms(tenant, entity_type, entity_id, attrs, tx_id, is_create)` — camino compartido por la entidad madre Y las proyecciones de saga (mata la segunda duplicación).
- `DatomPlan { datoms, fts_requests, delta, deleted_attrs }`.

Tests de caracterización unitarios (sin DynamoDB): create escribe los datoms esperados, update genera par retract/assert correcto, update/delete de inexistente → Eav002, atributo desconocido → Eav004, delta sólo con cambios reales, deleted_attrs en delete.

**Fase 4 — Orquestación unificada.** `transact_inner(payload, TxOptions)` único; `transact_bulk_deferred` = wrapper con `CachePolicy::Deferred` y sin proyecciones/constraints (comportamiento idéntico). Aquí se aplican 2 de los 3 fixes de seams:
- `suppress_events` gobierna también el outbox de las proyecciones (hoy lo ignoran).
- El despacho FTS se reordena tras el commit (materializado en Fase 5).

**Fase 5 — `cache_policy.rs` + `fts_dispatch.rs`.**
- `invalidate_entity_caches(tenant, entity_id, entity_type, &[SagaProjection])`: invalida EAV_CACHE por entidad (madre + cada proyección) y AEVT por (tenant, entity_type) de la madre Y de cada proyección — **fix: hoy las proyecciones (p.ej. scheduled_job) quedan con cache stale**. La ruta bulk de `janus_router/oltp_channel.rs:206` reusa la parte AEVT del mismo módulo.
- `FtsDispatch { spawn(ddb, table, reqs) -> Self, await_all() }` — encapsula chunks de 25 + `tokio::spawn` + log de errores. **Fix: el spawn se ejecuta DESPUÉS del `transact_write`**, evitando que una TX fallida contamine el índice trigram.

**Fase 6 — Limpieza.** Doc comment de `transact` devuelto a `transact` (hoy documenta a `reader`, `transact.rs:152`) y actualizado (ya no "chunk a 100"); mensaje de error de `:518` sin saltos/espacios literales; label "delete pull failed" → mensaje neutro; `pub use` finales en `writer/mod.rs`; `cargo clippy` sin warnings nuevos.

## Fixes de comportamiento incluidos (los 3 del seam)
1. FTS después del commit ACID (evita índice contaminado con TX fallidas).
2. Invalidación de cache para entidades proyectadas (EAV_CACHE + AEVT).
3. `suppress_events` suprime también el outbox de proyecciones.
