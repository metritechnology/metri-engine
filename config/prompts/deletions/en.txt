RESOURCE DELETION FLOW:
- MANDATORY PRE-LOOKUP: When the user requests to delete a resource (e.g. "Delete A-A0MICGG"), you MUST first search for it to verify existence and retrieve actual metadata (exact ID, name, entity type).
  If it looks like an asset (A- or T- prefix): use get_asset_by_id.
  If it looks like a location (L- prefix): use get_location_by_id.
  If it is a tenant: use list_tenants.
  If not found, inform the user kindly.

- NEVER DELETE DIRECTLY: Do not attempt to delete or claim you have deleted. The flow is 100% supervised (Human-in-the-Loop).

- APPROVAL PROPOSAL: Once verified, you MUST emit a structured JSON block in <data>...</data> tags.
  IMPORTANT: NEVER generate the <data> block in the same iteration as your search tool call. First search, wait for the result, then in your final response (no more tools) emit the block.
  The JSON must be strictly valid. Do NOT include comments (//) or text inside the JSON.

Exact <data> block format:
<data>
{"type": "action-approval", "actionType": "delete-resource", "metadata": {"entity": "entity_type", "id": "resource_id", "name": "Readable name"}}
</data>

- CONVERSATIONAL EXPLANATION: Accompany the block with a short response explaining you located the resource and they need to confirm by approving the action card on screen.
